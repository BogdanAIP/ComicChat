# ComicChat — дорожная карта

**Версия плана:** 2026-10-01 · **Статус:** план, а не отчёт о выполненной реализации.

## Цель

Сделать работающую приватную двустороннюю переписку, где каждое введённое текстовое сообщение немедленно занимает место **визуального** комикс-кадра, затем обновляется готовой иллюстрацией; обоим участникам доступна одинаковая история, но AI-расходы отправителей полностью разделены. После этого добавить интеграцию в ChatGPT и развивать социальные функции.

## Обязательные инварианты (не ослаблять ради скорости разработки)

1. Новое сообщение создаётся одним `message_id`; визуальная заглушка и финальный кадр — **разные состояния одной записи**, а не два сообщения.
2. Основная история всегда визуальная. Исходный текст хранится отдельно и доступен по действию; AI не переписывает цитату в речевом пузыре.
3. Авторство, порядок, доставка, ретраи и публикация изображения идемпотентны; при переподключении два участника видят одну и ту же версию.
4. Постоянные ID персонажей/референсов, настройки стиля на беседу, внятная политика смены сцены.
5. AI-задание запускается **от идентичности отправителя**; транзакционный ledger фиксирует `sender_id`, `provider`, `billing_source`, `job_id`, `status`. Ни одного неявного переключения на чужую подписку.
6. Приватность: только участники читают личные сообщения/объекты; подписанные URL или иная серверная проверка доступа, безопасная авторизация, согласие обоих участников для публикации переписки.
7. Сбой AI не теряет текст и не ломает визуальную ленту: fallback-панель, статус и повторная попытка.

## Этап 0. Зафиксировать и исследовать fork — P0

- [ ] Сохранить upstream provenance и MIT LICENSE; настроить origin/upstream.
- [ ] Воспроизводимая установка, lint/build/test: сравнить README, `package.json`, lockfiles, фактические версии Next.js/React.
- [ ] Ревизия схемы Supabase/RLS, realtime, DMs, storage, auth, серверных обработчиков и внешних зависимостей.
- [ ] Выявить лишние функции (email/voice/Cloudinary/публичные комнаты), не удаляя их без инвентаризации.
- [ ] Закрепить branch/PR workflow, секреты в env, запрет их коммита; добавить минимальный CI и smoke-тесты.
- [ ] Проверить, можно ли развернуть существующее приложение **без модификации** как baseline.

**Выход:** воспроизводимый upstream baseline, таблица reuse/refactor/remove, список несовместимостей и технических рисков.

## Этап 1. Вертикальный срез реальной переписки — P0

- [ ] `User`, `Conversation`, `Membership`, `Message`, `GenerationJob`, `Asset`, `CharacterProfile`, `UsageLedger`.
- [ ] Два участника, приглашение, изоляция личного чата, отправка/получение через одну серверную API-границу.
- [ ] Статусы `queued → rendering → ready | failed`; атомарное создание сообщения и задания; client-generated idempotency key.
- [ ] Realtime + восстановление после offline, строгий порядок, unread/ack.
- [ ] Тесты на двойную отправку, конкуренцию, reconnect, отсутствие утечки сообщений чужому участнику.

**Выход:** два независимых аккаунта могут переписываться между двумя браузерами и видят одинаковую историю после перезагрузки.

## Этап 2. Comic-first UX — P0

- [ ] Вместо текстовых bubble показывать визуальные карточки уже в момент отправки.
- [ ] Унифицированные входящие/исходящие панели, понятный прогресс, failure/retry **на том же `message_id`**.
- [ ] Отдельная команда «копировать исходный текст»; alt-text, keyboard navigation и удобочитаемый текст для доступности.
- [ ] Длинные реплики: адаптивный bubble или несколько панелей одного сообщения без пропусков текста.
- [ ] Демо-режим без AI: шаблонные герои, позы, фон, эмоции, пузырь и точный шрифт.

**Выход:** при скролле и перезагрузке нет смеси обычных текстовых сообщений с комиксами, даже при ошибке генерации.

## Этап 3. Render/AI pipeline — P0

- [ ] `GenerationProvider` с реализациями `TemplateRenderer`, `MockProvider` и разрешённым `OfficialImageAPIProvider`.
- [ ] Разделить генерацию иллюстрации **без букв** и программное наложение текста без изменения оригинала.
- [ ] Character reference sheet / фиксированный стиль / контекст сцены / user-controlled редактирование.
- [ ] Queue, bounded retries, timeout, deduplication, rate limits; хранить оригинал, изображения и версии генераций.
- [ ] Предварительное отображение стоимости или источника оплаты, отказ без скрытого списания; проверять пользовательские лимиты.
- [ ] Набор quality checks: fidelity текста, узнаваемость героя, 2-user delivery, долгие и эмодзи-сообщения.

**Выход:** генерация одного сообщения не блокирует другие, герой последователен, текст точен, стоимость прозрачно привязана к отправителю.

## Этап 4. Хостинг/переносимость — P1 (отдельный проверочный gate)

- [ ] Провести **deployment spike** для ChatGPT Sites: сборка/допустимые runtime APIs, хранилище, D1/R2, auth, realtime, cron/queues, лимиты и приватные объекты.
- [ ] Определить, какая часть Next.js и Supabase может быть переиспользована, а какая требует адаптеров или миграции.
- [ ] Если Sites проходит end-to-end тест двух клиентов, перенести persistence на совместимые адаптеры. Если нет — выбрать документированный переносимый backend без блокирования MVP.
- [ ] Автоматические миграции, резервные копии, экспорт/удаление данных, логирование без секретов; измерить фактические расходы.
- [ ] Домен, деплой из GitHub, staging и rollback.

**Выход:** публично доступная защищённая веб-версия, которую можно перенести на другой хостинг без изменения бизнес-логики.

## Этап 5. Sign in with ChatGPT / разрешения — P1

- [ ] Официальный поддерживаемый sign-in для данной формы приложения и категории доступа; тест двух независимых пользователей.
- [ ] Отдельно хранить локальную идентичность ComicChat и связку с OpenAI; token storage только на доверенной стороне.
- [ ] Отзыв доступа, истечение токена, logout, consent, account linking и управление настройками расходов.
- [ ] Не запрашивать доступа к личной истории ChatGPT; не помещать токены в URL, браузерное хранилище или логи.

**Выход:** отдельные учётные записи, отзыв доступа не ломает чужие сообщения, никакие токены не видны клиенту.

## Этап 6. Персональная оплата изображения — исследовательский gate, НЕ заявлять готовой

- [ ] Проверить документированную границу между Sign in with ChatGPT **Identity**, ChatGPT **Plan Usage**, локальным Codex imagegen и обычным оплачиваемым Images/Responses API.
- [ ] Получить допустимый режим для **удалённо размещённого многопользовательского приложения** и явное разрешение на генерацию изображений за счёт личных ресурсов пользователя.
- [ ] Провести двухаккаунтный тест: генерация А списывается только с А, генерация Б — только с Б, нет cross-account leakage, лимит каждого обрабатывается независимо.
- [ ] При отсутствии официальной поддержки сохранить `TemplateRenderer` и явный API-backed/ComicChat-credits вариант; **не использовать скрытые API/чужой OAuth client_id/cookies**.
- [ ] Настроить UI «кто платит и из какого источника», аудит и reconciliation статусов без доступа приложения к чужому балансу.

**Выход:** либо проверенный и разрешённый sender-pays режим, либо явно помеченный backlog/альтернативная оплата. Это НЕ блокирует базовый мессенджер.

## Этап 7. ComicChat внутри ChatGPT — P1

- [ ] Отдельный ComicChat MCP plugin поверх тех же backend/API, без дублирования базы.
- [ ] Исследовать Plugin Extensions: sidebar/fullscreen, deep links, conversation panel, event notifications; проверить фактическую доступность web/mobile/desktop у тестовых пользователей.
- [ ] Логин и привязка профиля; открытие нужного диалога по ссылке; chat UI с comic-first composer.
- [ ] Кросс-клиентская синхронизация: веб-версия и плагин отображают одно сообщение по одному ID.
- [ ] Review требований публикации/permissions, надёжное поведение вне ChatGPT.

**Выход:** пользователь может продолжить тот же приватный диалог в собственной веб-версии и поддерживаемом интерфейсе ChatGPT.

## Этап 8. Закрытая beta и безопасность — P1

- [ ] Тест на нескольких парах пользователей: удержание интереса после эффекта новизны; доля успешных кадров, задержки, ошибки, расходы.
- [ ] Приватность по умолчанию, жалоба, блокировка, удаление/экспорт, согласие на публичную публикацию, меры против спама.
- [ ] Нагрузочные тесты, квоты/anti-abuse, проверка RLS/IDOR, доступ к медиа и OAuth угрозы.
- [ ] Политика хранения исходного текста и изображений; понятное уведомление о внешних провайдерах генерации.
- [ ] Список известных ограничений и процедура реагирования на инциденты.

**Выход:** проверенная закрытая beta, а не демонстрация с одним аккаунтом.

## Этап 9. Социальные механики — P2, после успешного 1:1

- [ ] Групповые комикс-чаты и устойчивый порядок нескольких авторов.
- [ ] Совместные визуальные миры, галерея персонажей и управляемая смена стилей.
- [ ] Опциональная публичная лента/подписки/главы, только по согласию участников.
- [ ] Экспорт страниц/PDF, мультипанельный режим, Telegram bridge.
- [ ] Монетизация творческих возможностей без принудительного доступа к личным перепискам.
